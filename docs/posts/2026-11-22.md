## 今日最值得知道

METR 更新公共模型能力评测，发现可完成任务的时长指标继续增长，同时强调缺少清晰反馈时的判断仍难衡量。推理服务迁移与语音计费也带来具体工程变化；新的并发 Agent 研究则把上下文调度和合并后的结果验收拆开比较。

### 本次新增 · METR 发现任务时长指标继续增长，验证困难仍是边界
<!-- news: research -->

METR 在 TH1.1 的 222 项和新增 TH2 的 36 项任务上评测公共模型，报告成功率为 50% 时、按人类耗时标定的任务时长约每 3.61 个月翻倍，95% 区间为 2.08–4.94 个月；这不是模型连续运行时间。**判断**　长任务试点仍需单独测试缺少快速反馈的判断环节。仅 9% 的人类耗时估计直接来自人工基线，其余结合资料、专家估计与外推；新任务偏向研发场景，不能据此预测普通岗位何时可自动化。

Megan Kinniment 等（METR） · 2026-11-20（报告首发，源站日期） · [摘要、方法、结果与局限](https://metr.org/blog/2026-11-20-q4-2026-capability-update/)

### TensorRT-LLM 1.3 移除旧后端，升级要先核对兼容性
<!-- news: tools -->

NVIDIA 发布 TensorRT-LLM 1.3.0，移除 TensorRT 后端及旧 C++ Executor，PyTorch 成为唯一后端；新增 DeepSeek-V4、Kimi K3 支持，Rubin 支持仍为预览。发布说明还列出 Responses 接口在续接会话、流式事件和部分工具调用上的兼容缺口。**判断**　升级应先盘点旧构建命令和接口，再按模型、GPU、量化配置回归测试。新增支持不等于所有组合可用，说明中仍有分离式服务可能产生错误输出的已知问题，也不能据功能列表推算提速幅度。

### GPT-Live-1.1 开放 API，待机降价只覆盖语音会话部分
<!-- news: models -->

OpenAI 开放 GPT-Live-1.1 API，并为 1 和 1.1 的 WebRTC 会话提供待机配置：静默 5–60 秒后暂停推理，连接保持，用户说话时恢复。官方列出待机每分钟 0.02 美元、活跃时 0.05 美元，后端模型与工具另计；未配置超时则唤醒后持续活跃。**判断**　长连接语音应用可按真实静默占比测算成本。文档提醒，待机后的短句首响可能更慢；更自然的口音和转录改善属于官方描述，公告未给量化评测，不能据此推断业务完成率。

### Deepgram 把按次语音支付接入 AWS 账单，仍需预算授权
<!-- news: industry -->

Deepgram 宣布，Agent 可通过 AWS Marketplace 和 x402 按请求购买 Nova-3 转录、Flux TTS 与 Aura-2 合成，无需 Deepgram API 密钥，费用计入 AWS 账户。商家页面要求先建立带支出限额的 AgentCore 支付会话，再取得报价、支付并重发请求；已付报价有效五分钟。**判断**　这为临时调用语音能力增加采购入口，授权和对账仍需由应用落实。当前说明覆盖三个批处理端点，转录结果同步返回且不支持回调，不能当作所有实时语音接口均已支持；也没有证据说明这种结算方式必然降低总成本。

### 本次新增 · 并发 Agent 可直接调度上下文，合并结果仍需验收
<!-- news: research -->

Xufei Tian 等提出 ClonAct，直接路由到独立上下文，保留澄清记录，并在写回前隔离试合并。作者在 Synaptic-Bench-150、DeepSeek-V4.1-Flash-1017 上报告，相对 DSH-SuperAgent 提示 token 少 45.9%，通过率为 74.7% 对 72.0%，差异未达统计显著。**判断**　并发编程应把合并后测试纳入验收。对照显示，试合并门也能移植给原方案；流式实验仅含三个无代码冲突的输入流，不能外推到大规模冲突协作。

### Seer 先模拟搜索动作，再把真实结果写入证据链
<!-- news: research -->

Yuhao Zhou 等训练共享的工具返回模拟器与价值估计器，先比较候选动作，仅执行选中项，避免为弃选分支付工具费。主 Agent 权重保持冻结，预测内容不作为最终引文，只将真实工具返回写入执行历史。作者在 GAIA 上报告，Qwen3.5-4B 的准确率由单轨迹基线 13.6% 升至 41.7%，四轨迹多数投票为 21.4%；Seer 使用 32 个候选，计算预算并不相等。**判断**　值得比较额外推理能否抵消工具费。五项基准主要检验最终答案正确性，尚未衡量报告覆盖度与引文支持；两套辅助模型均为 9B，且未实测设备峰值内存、能耗或时延，不能视作端侧低成本已获证明。

Yuhao Zhou 等（四川大学、伊利诺伊大学厄巴纳—香槟分校、联想） · arXiv 预印本 · 2026-11-19 17:03 UTC 首次提交（北京时间 11-20，11-20 列表公布，v1） · [论文与版本](https://arxiv.org/abs/2611.26423) · [方法、实验与局限](https://arxiv.org/html/2611.26423v1)

### GLiDE 将推理蒸馏为候选概率，增加计算仍会增加时延
<!-- news: research -->

Fastino Labs 新论文用双向注意力与多教师软标签训练决策模型，不生成文字而直接为候选评分。方法移除部分注意力层的因果遮罩，让问题与选项互相读取；输出范围仍受给定候选限制。作者报告，27B 的 V1.2 在 Hugging Face Decision Index 隐藏集得 71.52 分，Jeffan-31B 为 69.75；权重平均叠加中间层重复计算后达到 73.37，单张 RTX PRO 6000 的中位时延从 92.9 增至 122 毫秒。**判断**　路由与分类可同时验收准确率、延迟和拒答阈值。增分包含两种改动，不能全归给重复计算；校准误差来自特定测试样本，不保证新业务中的置信度同样可靠。
