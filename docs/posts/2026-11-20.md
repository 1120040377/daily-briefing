## 今日最值得知道

谷歌把工具检索、Mac 电脑操作和交互世界进一步变成可调用的产品能力，Ai2 则让文献假设生成进入科研平台并开放代码。随着 Agent 的接入范围扩大，新记忆研究提醒团队：增加经验可能提高完成率，也可能推高成本，收益需要按模型与任务实测。

### 工具参数按需加载进入 Gemini API，名称和描述仍占上下文
<!-- news: tools -->

Google 在 Interactions API 预览 Tool Retrieval，支持 Gemini 3.6 及后续模型。服务端模式仍让模型看到全部延迟加载工具的名称和描述，只在需要时补入完整参数结构，同一次请求内完成检索与函数调用。功能不单独收费，已加载参数仍按输入 token 持续计费。**判断**　大工具库可同时测试选择准确率、账单和缓存命中率。省下多少取决于未加载参数的体积；使用自有客户端检索还会增加往返。

Lucia Loher（Gemini API 产品经理）、Nora Kassner（Google DeepMind 研究科学家） · 2026-11-19（首发） · [机制、计费与适用模型](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)

### 本次新增 · Agent 记忆并非越多越好，应按模型测量收益与开销
<!-- news: research -->

K. R. Jayaram 等从 Agent 的成功、失败轨迹提炼经验，合并重复项并保留来源，再比较全量注入与检索筛选。作者在 AppWorld 的 168 项常规测试上报告，DeepSeek-V3.2 加入 191 条指南后，任务完成率从 79.8% 升至 89.3%，但 token 增加 78%；gpt-oss-120b 全量为 51.2%，筛选约 29 条后两次均值为 55.4%。**判断**　记忆数量应与完成率、成本一起调优。配置直接在测试集上比较，多数仅跑一次，尚不能推出跨任务通用最优用量。

K. R. Jayaram 等 · arXiv 预印本（作者注明获 IAAI 2027 口头录用） · 2026-11-19 16:29 UTC 首次提交（北京时间 11-20，11-20 列表公布，v1） · [论文与版本记录](https://arxiv.org/abs/2611.26361) · [方法、实验与局限](https://arxiv.org/html/2611.26361v1)

### Gemini 开始操作 Mac 应用，首批限美国英语个人订阅用户
<!-- news: agents -->

Google 为 Mac 版 Gemini 推出电脑操作，可跨本地文件、桌面应用和网页完成多步任务。官方称，它在独立后台窗口运行，用户选择可访问应用、观看预览并批准关键动作。首批面向美国英语、18 岁以上个人账户的 AI Plus、Pro、Ultra 用户，要求 Apple Silicon 和 macOS 15.0 以上。**判断**　可先用可回退的跨应用流程验收。发布说明未给完成率，隔离窗口和人工批准也不能代替业务结果回执。

Michael Friedman（Gemini App 产品负责人） · 2026-11-19（首发） · [功能、地区与设备条件](https://blog.google/innovation-and-ai/products/gemini-app/computer-use-mac/)

### 本次新增 · Genie 4 从订阅体验扩展至开发者 API
<!-- news: models -->

继前一天在 Project Genie 扩大开放后，Google 宣布 Genie 4 可通过 Gemini 的 Interactions API 和 AI Studio 调用。官方称，文本、参考图或二者组合可生成连续的 720p、每秒 24 帧世界，并同步生成原生音频；键盘操作和实时文字可改变场景、对象与事件。输出带 SynthID 水印。**判断**　开发者可以开始测试可交互原型。公告提出机器人与 Agent 训练用途，但没有提供模拟到真实环境的迁移效果，尚不能把它视为已验证的训练替代品。

Google · 2026-11-19（API 开放首发，订阅入口更新为 11-18） · [API 开放说明](https://blog.google/innovation-and-ai/technology/developers-tools/genie-4-in-gemini-api/)

### 本次新增 · Theorizer 在 Asta 上线，将文献证据转成可检验假设
<!-- news: agents -->

Ai2 将科研 Agent Theorizer 加入 Asta，并开放代码。它先检索文献、按问题设计抽取模板，再综合发现并为解释关联出处；网页版限开放获取论文。官方案例中，它提出的气候异常解释被研究者排除，却引导团队发现原始数据估计的缺陷，后续独立验证仍在进行。**判断**　它适合扩展待检验问题，不能把带引文的解释直接当成发现。工具可能漏检旧文献、误判原创性；本次新增是产品入口与代码开放，非新论文发表。

Ai2 · 2026-11-19（产品公告首发，源站日期） · [机制、案例与限制](https://allenai.org/blog/theorizer-in-asta) · [代码及使用范围](https://github.com/allenai/asta-theorizer)

### ROCm 10.2 更新推理框架，压缩目录会增加首次加载开销
<!-- news: tools -->

AMD 发布 ROCm 10.2.0，提供更新的 vLLM 0.32.0、SGLang 0.5.21 构建及 PyTorch 2.15 安装包。官方称，hipBLASLt 的方案选择目录在 Debian、RPM 包中压缩后，磁盘占用从约 3.8GB 降至 194MB，但首次调用需解压。版本说明仍列出部分 MI350 系列训练吞吐下降问题。**判断**　升级应分别验证冷启动、稳定吞吐和现有模型兼容性。目录变小不代表显存需求同步下降，也不保证每种负载都更快。

Amy Wiebe 等（AMD） · 2026-11-18（首发） · [更新概览](https://rocm.blogs.amd.com/ecosystems-and-partners/rocm-10.2-blog/README.html) · [已知问题与修复](https://rocm.docs.amd.com/en/docs-10.2.0/about/release-notes.html)

### 一次微调适配多种虚假事实，为对齐审计提供候选方法
<!-- news: research -->

Ananya Sutradhar、Fabien Roger 将多种虚假事实与合成文档配对微调，替代每组事实分别训练模型。作者在 Qwen3-8B 的简单留出问题上报告，采用提示中虚假事实作答的比例由原模型 0.09 升至训练一万条事实后的 0.86；另测因果推断和费米估算。**判断**　这可能降低构造审计情境的成本，但不等于证实模型具有真实信念。主要留出事实与训练数据同源，初步 Agent 审计也未明确优于直接改系统提示。

Ananya Sutradhar（Anthropic Fellows、MATS）、Fabien Roger（Anthropic） · arXiv 预印本 · 2026-11-18（UTC 与北京时间首次提交同日，11-19 列表公布，v1） · [论文记录](https://arxiv.org/abs/2611.23938) · [方法、实验与局限](https://arxiv.org/html/2611.23938v1)

### Dean Ball 主张让 Agent 权限可理解、动作可审计、授权可撤回
<!-- news: industry -->

Dean Ball 在 OpenAI 官网发表演讲改编文章，提出即使每次委托都符合商业效率，累积起来仍可能让人失去对机构的实际主导权。他主张把人的责任与 Agent 动作联系起来，同时保留隐私及数据迁移能力。文中明确这是作者个人观点，不必然代表 OpenAI。**判断**　企业可把授权撤回和动作追踪纳入产品验收。文章讨论的是制度选择与长期情境，不能据此推断公司已出台相应政策，或预测自治企业必然取代人类管理。
