## 今日最值得知道

Claude Ship 开始把代码审阅后的修复和审批政策接入同一流程，GLM-5.4 则进入 Coding Plan，为编程工具增加模型选择。企业零留存方案、智能问数拒答与缓存迁移研究共同把注意力推向交付边界：哪些数据留下、哪些结果放行、模型更新后怎样继续执行，都需要明确验收。

### 本次新增 · Claude Ship 把 PR 修复和审批政策接入编程流程
<!-- news: tools -->

Anthropic 为 Team、Enterprise 的 GitHub 仓库推出 Claude Ship：新增测试版 PR Steward 处理检查失败、冲突及审阅反馈，Claude Approvals 按仓库政策决定是否批准，既有 Code Review 已正式开放。Steward 本身不批准或合并，实际合并仍受权限与分支规则约束。官方说明按 token 计费，零留存、HIPAA 或自管密钥组织暂不可用。**判断**　可先用观察模式检验审批与人工判断的一致性，再评估审阅耗时、漏检和额外费用。

### 本次新增 · GLM-5.4 进入 Coding Plan，推理强度需要按任务调整
<!-- news: models -->

Z.ai 的 ZCode 4.0.0 发布记录确认 GLM-5.4 已上线 Coding Plan，新增视觉能力。官方文档列出百万 token 窗口、Low、High、Max 三档推理强度，默认最高档，Lite、Pro、Max、Team 均可用；支持 Coding Plan 的其他工具也能切换。官方同时提示，高档会拉长思考并加快额度消耗，旧版 GLM-5.3 仍保留。**判断**　选型应同时比较任务成功率、时延和完整任务消耗；简单修改可测试较低推理强度，长窗口本身不能证明长任务可靠性。

### GPT-6.2 开始进入 ChatGPT 聊天入口
<!-- news: models -->

OpenAI 宣布向 Plus、Pro、Business 和 Enterprise 逐步推出为日常聊天调校的 GPT-6.2 Sol 版本。本次新增是聊天入口的可用性，Work 和 Codex 所用模型未随此次更新改变；企业账户还受管理员设置影响。官方称，聊天内部测试的图像理解得分从 GPT-6 的 47.4% 升至 71.7%。**判断**　可以用自己的图像和复杂指令任务重新验收效果，官方内部得分不能直接换算成个人工作的成功率。复杂指令测试也由 62.5% 升至 78.1%，仍应结合真实任务核验。

### Gemini 文件切片让 Agent 只读取需要的部分
<!-- news: agents -->

Google 为所有 Gemini 4 模型推出服务端文件切片：文件上传一次后，可跨轮次复用地址，选择文档页码、表格单元格或音视频片段，也能选择文字、图像等内容层，并原生接收 Office 与 OpenDocument 文件。官方称仅对模型实际检查的部分计入 token；整个上传文件仍受原有大小和页数限制。**判断**　文档 Agent 可先用文字定位，再精读图表，减少无关上下文；应同时测试切片是否遗漏跨页证据，不能只比较单次请求费用。

<!-- news: industry -->

Anthropic 在 Claude Platform 及其托管的 AWS、Google Cloud 平台推出 EFS 测试，面向符合条件的组织。官方称不留存提示词与回复；加密安全副本写入客户自有桶，自动安全监测继续，人工审查由客户负责。客户无法直接读取该加密格式。方案覆盖配置工作区的 Messages API 请求，不覆盖文件上传、批处理结果和托管 Agent 会话等功能数据。**判断**　企业选型要逐项核对数据位置、审查责任和功能兼容性，不能把零留存标签套用于整个平台。

### 企业访谈显示，代码提速后瓶颈向审查和决策移动
<!-- news: industry -->

Anthropic Institute 对 58 家美国企业客户进行 66 次访谈，受访者更多将 AI 价值归于扩大产出，而非削减成本；代码生成变快后，审查、销售和战略决策需要跟上。部分企业因此扩大员工职责，把人调向新的瓶颈。访谈每次 25–40 分钟，采用非随机样本，偏向软件和金融企业，甚至不能代表全部 Anthropic 客户。**判断**　试点应衡量端到端交付与返工，而非仅统计生成量；这项定性研究不能推断全经济的生产率或就业因果。

Nathan Wilmers、Maxim Massenkoff、Peter McCrory／Anthropic Institute · 2026-11-23（首发） · [报告](https://www.anthropic.com/research/working-with-ai) · [全文 PDF](https://assets.claude.com/0cb09418f04d09baf72922e53a3f17383ef838c9.pdf)

### 本次新增 · Text-to-SQL 用校准拒答降低放行结果中的错误
<!-- news: research -->

Domyn 团队让不同模型分别生成 SQL、审查执行结果，以随机森林融合信号，再用标注集校准拒答阈值。作者在 Spider 上用 GPT-OSS-120B 生成、Gemma-4-31B 审查：设 15% 风险预算、失败概率 0.1，十次重划分平均放行 52.4% 查询，放行部分实测错误率为 9.1%，不拒答时为 22.6%。**判断**　智能问数应同时验收错误率与覆盖率。这是 arXiv 预印本的作者自报；同一阈值直接迁至 BIRD，错误率升至 30.1%，统计保证依赖校准与部署数据同分布，不能直接搬到企业库。

### 本次新增 · LiveLoRA 让适配器更新时重建缓存，减少长历史重算
<!-- news: research -->

LiveLoRA 冻结底层并固定末层 K/V 适配器下投影，重建缓存后统一切换模型版本，避免更新适配器时重算全历史。作者在单 H200、Qwen2.5-3B、8K 历史的受控实验中，每 32 或 128 token 更新时，更新加解码耗时较全历史重算减少 16.24% 和 3.90%，不含训练与初次预填充。**判断**　长期 Agent 在线学习可关注版本一致性与更新频率的共同设计。这是 arXiv 预印本的作者自报，实验使用合成适配器更新，尚未验证真实任务学习收益或分布式服务。
