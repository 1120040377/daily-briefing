## 今日最值得知道

模型与硬件继续升级，两项新研究进一步把焦点移到 Agent 的交付和记忆：发现待办不等于完成，摘要也不能只追求压得短。结合推理缓存与软件界面复用，今天重点看实际状态、证据和完整成本能否一起验收。

### Claude Fable 5.2 开放接入，复杂任务能力与价格一起变化

Anthropic 发布 Fable 5.2 与 Mythos 5.2，两者使用相同底层模型，后者的部分安全限制不同，须通过验证项目申请。官方称，相对 5.1，输出生成最快提高 30%；标准 API 每百万输入／输出 token 为 8／40 美元，快速模式为 16／80 美元。官方 FrontierSWE v2 得分从 Fable 5.1 的 56.3% 升至 69.9%。**判断**：可以用复杂迁移和长任务重新评估模型分工；厂商基准不能直接换算为团队提效，快速模式的速度也须与完整调用成本一起验收。

来源：[Anthropic 官方公告](https://www.anthropic.com/claude-fable-and-mythos-5-2)，2026-11-09。

### Google 新 TPU 系统分别针对机密推理和长上下文

Google 的 Amin Vahdat 宣布 TPU 8tx 与 8i Max，属于第八代芯片的系统配置扩展。8tx 配合第五代 AMD EPYC，在处理过程中保护数据与模型权重；8i Max 将两颗 8i 封装在一起。官方称，后者计算量、SRAM 和 HBM 带宽均为 8i 的两倍。**判断**：企业 Agent 的硬件选型开始更明确地区分数据保护与内存瓶颈；带宽翻倍不能等同于任务速度或性价比翻倍。公告未给出这两款系统的具体价格与交付日期，采购判断还需等待可用配置和实测。

来源：[Google 原始公告](https://blog.google/innovation-and-ai/infrastructure-and-cloud/global-network/tpu-8i-max-and-8tx/)、[Google Cloud 技术正文](https://cloud.google.com/blog/topics/ai-infrastructure/tpu-8tx-and-tpu-8i-max)，2026-11-09。

### 本次新增 · 主动 Agent 发现待办之后，仍会在交付环节丢分

Shiqi Chen 等用时间图构造模拟组织，让 Agent 从邮件、聊天及业务记录自行发现义务，再按工作区实际变化验收。同一框架下，17 个模型各跑三次、每次 120 项任务；作者报告，最佳端到端加权得分为 0.698，发现查准率与执行得分仅弱相关。**判断**：主动助手应分别验收任务归属、是否已办结，以及最终记录、接收人和渠道。该评测仅来自一个生成世界，部分项目可获部分分数；冗余工作不扣端到端得分，不能把 0.698 当作真实企业全自动成功率。

来源：[arXiv 预印本 2611.12393](https://arxiv.org/abs/2611.12393)、[方法与实验](https://arxiv.org/html/2611.12393v1)，2026-11-09 UTC 首次提交，11 月 10 日列表公布；当前为 v1。

### 本次新增 · MaxIM 同时训练摘要的未来用途与证据一致性

Jihwan Jeong 等给增量摘要加入逐步信息奖励，既保留后续任务所需线索，也约束摘要与已见材料一致。在 338 篇留出论文、500 token 记忆预算下，作者报告，带弃答和错答惩罚的百分制选择题得分由仅任务奖励训练的 54.44 升至 66.39；这不是普通正确率。**判断**：记忆压缩可同时验收后续可用性和事实依据。实验基于 Gemini 2.5 Flash，并含模拟对话与模型裁判；转入新领域仍需构建训练目标，训练开销增加，误删的历史也不能自行找回，仍需检索兜底。

来源：[arXiv 预印本 2611.12825](https://arxiv.org/abs/2611.12825)、[方法与实验](https://arxiv.org/html/2611.12825v1)，2026-11-09 UTC 首次提交（北京时间 11 月 10 日），11 月 10 日列表公布；当前为 v1。

### CPU-ARC 将重复推理变成代码，省钱前要先摊销构建成本

Peter Belcak 等将推理轨迹拆成可复用的语义函数，以 CPU 代码和小模型处理新参数，失败时回退大模型。作者在 MATH-500 上报告：缓存准确率 98.8%，源模型 Claude Opus 4.5 为 98.6%；各测试配置调用成本约为源模型的 1/16—1/291，但一次构建约需原调用成本的 12—84 倍。**判断**：适合先试重复指令、变化载荷的任务。成本按论文指定 API 价格估算，实验集中于数学和科学题，扰动验证还依赖模型裁判，尚不是生产 Agent 的净收益证明。

来源：[arXiv 预印本 2611.09891](https://arxiv.org/abs/2611.09891)、[方法与实验全文](https://arxiv.org/html/2611.09891v1)，2026-11-06 UTC 首次提交（北京时间 11 月 7 日），11 月 9 日列表公布；当前为 v1。

### 软件界面让同一个电脑操作 Agent 参与多类具身任务

Pranjal Aggarwal、Sean Welleck 为导航、三维分割等任务搭建界面，保持同一 Agent 框架，通过截图、键鼠操作已有功能。作者报告，四项 ECCV 工作坊竞赛取得第一、第二、第三和第六；OpenSUN3D 的 AP50 为 25.88，最佳其他参赛方案为 21.45。另在四项验证子集比较 GUI 与 API，同模型得分差均不超过 4 分。**判断**：值得探索通过软件复用通用交互能力。任务专用功能仍由软件提供，这些结果不能证明真实机器人连续控制已解决；通用具身模型仍是作者提出的方向。

来源：[arXiv 预印本 2611.09847](https://arxiv.org/abs/2611.09847)、[方法与实验全文](https://arxiv.org/html/2611.09847v1)，2026-11-06 UTC 首次提交（北京时间 11 月 7 日），11 月 9 日列表公布；当前为 v1。
